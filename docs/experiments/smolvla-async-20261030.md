# 2026-10-30 SmolVLA：异步提前推理离线验证

对应[主计划P2A](../plans/smolvla-training-rollout-plan-20261030.md)。本次验证本机RTX5060Ti上真实SmolVLA推理与CPU动作队列并行运行，使用录像，未连接相机、串口或机械臂。

**结果：正常离线20Hz预算通过，压力场景按预期未通过。** 模型本身仍需约150ms生成一块动作，后台提前推理消除了执行线程的周期性等待。此结果证明当前机器的动作供给计算能力，不代表实机抓取、低延迟反馈或动作平滑已经通过。

## 实现与复现

脚本：[tools/smolvla_async.py](../../tools/smolvla_async.py)；复现命令见[tools说明](../../tools/README.md#smolvla-异步提前推理检查)。环境沿用 `/data/work/venvs/so101-smolvla-061` 和[同步smoke](smolvla-local-smoke-20261030.md)已固定的官方模型revision、FP32、两路相机映射、512×512补边、50步动作块及10步去噪。

后台单个worker独占模型和处理器，在自己的CUDA stream推理、反归一化后整块转CPU。执行线程不做GPU同步或预处理，以绝对20Hz时间表消费动作；剩余10步（500ms）请求新块，最多一个在途请求，包括尚未领取的结果。

新块以请求时的目标tick为起点；返回后裁掉已经过去的前缀，替换未来队列。所有消费动作检查任务代次和颜色。切换任务/reset清空CPU队列，旧代次在途结果丢弃；模型状态仅由worker重置，避免跨线程reset/predict竞争。

输入为各已验收green/red派生集首episode前32个连续帧及6维状态，预载CPU并按控制tick循环回放。source metadata确认640×480后再解码。缓存回放没有真实闭环反馈；观测年龄指回放快照的请求时间到动作消费的时间，不是相机链路延迟。

最终调度允许5ms操作系统唤醒迟到；超出后跳到未来tick并记skip，不补发历史动作。5ms是本次调度容忍窗口，不是硬实时承诺。首块预填充、指令切换等待和压力测试均单独计时，不并入正常稳态平均频率。

验收预算在主计划预先登记：零断粮、零跳步、零过期或跨任务动作被消费；有效动作频率19.8–20.2Hz，间隔P99≤60ms、max≤75ms、CPU工作max≤50ms。该预算用于离线计算调度，不代表实机节拍已通过。

## 实验设计与证据

证据根目录：`/data/work/so101-evidence/real-robot/smolvla-async-20261030/`。

- `probe-01/`：短诊断，不用于最终验收。
- `formal-fp32-01/`：首次90秒正式测量，保留完整raw、报告及对应`source.py`。复核后增加了49ms迟到边界的调度回归，再以新代码独立重测；不回写旧计时和旧哈希。
- `formal-fp32-02/`：最终冻结代码的90秒稳态、10秒切换后red回放、8秒延迟压力测试。包含命令、实际配置、events、逐tick JSON/CSV及报告。

压力测试在每个后续推理块完成后额外延迟发布800ms，使总供应时间超出500ms预取缓冲。主循环仍运行，但无动作时明确记starved，不插入hold或复制动作；有效动作频率单独统计，最长动作间隔跨越断粮段计算。

任务切换测试在旧请求的预处理/预测/后处理链路在途时切到red，断言`inference_start < switch_time < inference_end <= ready`。这个区间不是CUDA event，不能证明切换瞬间恰有GPU kernel运行。旧请求额外延迟发布50ms以暴露在途结果；总暂停含此人为延迟，不能直接当作自然切换耗时。

## 解释与部署前要求

基础异步可以隐藏模型约150ms的计算停顿，但新的动作块直接替换未来动作，并未做RTC前缀引导或平滑衔接。接缝差保留在raw报告，单位为base模型原生动作单位，不能解释为经过校验的SO101角度，也未设置平滑通过阈值。

当前500ms剩余量预取并不意味着反馈只落后500ms：一块动作有2.5秒预测范围，继续执行时观测年龄会增长。部署前应验证更短执行horizon、更频繁更新或RTC，结合微调后的抓取效果评价，而非只追求队列不断粮。

首次请求包含模型加载与5次warmup，因此首块观测时间戳也跨越冷启动。原始观测年龄必须保留；后续正式入口应先加载和预热，再取得新观测填充队列，不能直接使用加载前的旧观测。

本次未验证官方`lerobot-rollout --inference.type=rtc`入口、RTC平滑性、真实采集/串口开销或抓取成功率。下一步是将微调产物和所选正式异步引擎接入，保留任务代次屏障、异常停机/hold的明确语义，再验证完整硬件节拍。
