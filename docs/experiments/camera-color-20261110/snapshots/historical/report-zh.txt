相机颜色一致性调研与离线验证（2026-11-02）

结论：有条件改善可行，但当前证据不支持直接把两路调成相同参数，或直接部署软件白平衡。纸面通道增益能匹配纸面，却使红绿方块差异略大。优先固定光源、用中性灰/色卡验证硬件曝光与白平衡，再决定是否需要每路软件校色。没有色卡的“看起来更像”不能认定颜色准确，也未证明策略会改善。

本次边界
只读取仓库配置、现存preflight图和12条已录双路视频；以v4l2-ctl --info --list-ctrls-menus查询当前控制。没有设置任何相机控制，没有采新帧、开启采集流或动作，没有生成/覆盖生产配置，没有训练、部署、commit或push。所有新增内容仅在本证据目录。原图保留；视频尺寸先查询，图片先检查均640×480；拼图长边均≤1600。

设备与当前控制（不是历史录像时刻的硬件快照）
腕部：配置by-id usb-icSpring_icspring_camera-video-index0→/dev/video0，uvcvideo，驱动显示icspring camera，无序列号；仓库README记USB 32e6:9005。
侧面：配置by-id usb-icSpring_icspring_camera_202404160005-video-index0→/dev/video2，uvcvideo，序列号202404160005；README记USB 32e6:9221。以上足够绑定本次设备，不足以确定内部传感器、ISP型号或厂家响应曲线，未猜测这些参数。
当前值及范围（腕部 / 侧面）：
- 自动曝光：均1 Manual；exposure_time_absolute均40，范围均1–5000。按V4L2标准是4ms名义值；不能推断两路亮度相同。
- AWB：1 / 0；温度4000（inactive） / 3000K；范围均2800–6500。腕部AWB运行时读到的4000不是已锁定白点。
- saturation：25（默认25） / 110（默认57）；范围均0–128。
- gamma：67（默认67） / 115（默认115）；范围均1–500。
- contrast：27（范围0–64） / 32（范围0–63）；brightness均0（范围-128–127）；hue均0（-180–180）。
- power_line_frequency均1/50Hz；sharpness 4（0–15）/31（0–31）；backlight_compensation均0（0–1）。
- 本次枚举没有独立red_balance、blue_balance、gain或硬件3×3色矩阵接口；只能说标准公开接口没有列出，不能断言设备内部不存在。
不同设备可用控件、范围、默认值不同；同一数值不代表相同色彩响应，gamma的67/115尤其不能解释成数学gamma指数。AWB一开一关是潜在时变来源，但未通过改设置做因果实验证实。camera.env与当前读值基本一致；腕部饱和度为空代表脚本不改，不代表自动与侧面相同。侧面110是先前针对绿色发灰做的调整，应保留其历史语境，不能仅按数值偏大判错。

离线样本与方法
plan.json给出的12个dataset，每条observation.images.wrist/side的file-000.mp4，以libdav1d软件解码第一帧。是同条同帧序号/名义时刻，不是硬件曝光同步；side输入30fps与wrist20fps、异步读取意味着真实时间可有偏差。起始场景静止，适合颜色粗对比。还查看了YAaBMPL2的side/wrist-39.png；preflight按代码先采side后采wrist，不把它称作同步采样。
全部24个视频ffprobe均AV1、640×480、yuv420p、tv range、20/1；没有标注color_space、transfer、primaries。这使两路显式range不一致的证据不足，但不能完全排除上游YUYV/MJPG解码、RGB/YUV矩阵和压缩造成差异。对比preflight PNG也可见腕部方块较暗，故现象不是只出现在录制视频。没有检测到可据以宣称RGB/BGR颠倒的证据；本次RGB统计统一由PIL读PNG。

先在人工圈定方块窗口内筛取颜色优势像素并腐蚀边界，记录中位数，避免全图均值受构图影响。此mask以颜色为条件，会偏向可见彩色区域，不能当完整方块分类准确率。随后加做完全不含颜色阈值的固定小矩形内部patch，结果也显示强烈暗通道。roi-verification.jpg的青色是被统计像素；trial-XX-*-fixed-patches.png黄色框是固定小patch。纸面和木面独立取样；不同视角不同位置，不是相同入射光或同一材料点。

12条第一帧中，颜色优势区域中位RGB范围：
腕部纸：[218–222,201–207,215–220]；红：[60–67,0,0]；绿：[0–1,13–21,0–7]。
侧面纸：[196–197.5,190–192,194–197]；红：[154–171,30–36,43–50]；绿：[49–56,68–79,47.5–53]。
腕部纸亮而块暗，故不能用“全局曝光不足”独立解释；视角使方块不同面、阴影、反射条件差异很大，ISP色彩/色调响应也可能贡献，未分离因果。
无颜色筛选固定内部patch复核：
trial1腕红[50,0,0]，G/B为0占90.3%/87.5%；腕绿[0,1,0]，所有像素最大通道<32。
trial1侧红[189.5,31,43.5]，绿[55.5,76,55.5]，两块patch都没有零通道。
trial7腕红[21,0,0]、绿[0,6,1]；trial12腕红[27,0,0]、绿[0,4,0]。不是颜色mask单独制造的现象，但暗面选择、编码量化及局部受光仍限制解释。乘法增益无法恢复已经为0的通道信息；不能推断传感器原始RAW也已截断。

有限候选与留出结果
唯一候选：trial1纸面中位RGB拟合腕部到侧面的显示空间通道乘法，gain=[0.89545,0.92718,0.89545]；不拟合方块，无复杂矩阵/曲线搜索。它包含亮度匹配，不是物理照明估计，也不是线性RAW校色。
RGB欧氏距离（0–255显示空间；非DeltaE、非色准）：
trial1纸35.82→0；红112.00→117.42；绿95.40→96.29。
留出trial7纸32.06→3.75；红116.19→121.97；绿85.09→86.26。
留出trial12纸34.67→2.87；红119.72→125.80；绿86.06→87.36。
该候选在不同布局仍能匹配纸，但无法同时匹配块，因此不建议直接采用。正通道增益在这些已统计patch中仍保留红R优势、绿G优势，不过腕部绿接近黑，保留优势不等于机器人模型可靠识别。软件预览只用于观察失败模式，不是生产配置或推荐参数。

推荐验证顺序（本次均未执行）
1. 先复用训练期现有两路图像检查方块、纸和背景分布。两路本来允许不同颜色分布；单纯追求两路像会使现有训练/推理分布进一步偏移。若采集后改变校色，未来训练数据与推理都应采用一致版本；旧模型必须离线回放和受控机器人实验复核。
2. 固定漫射光源、遮掉混合色温与强反光，放同一灰卡/标准色卡到方块所在平面，尽可能让两路看到同一色块正面；包含腕部不同姿态、纸面亮区及方块暗面，查看AWB预热和跨帧漂移。不把普通白纸当已知中性标准。
3. 独立为每路寻找保留白色高光及暗色块细节的曝光/色调设置，优先测灰阶，而不是同时调整曝光、WB、gamma、饱和度。取得稳定中性灰后，验证锁白平衡是否改善时变；设备的单一Kelvin接口未必能补绿/洋红轴，也不保证两台同K一致。
4. 若硬件稳定后多色块仍有系统差异，再以色卡测量建立每路软件映射，处理正确颜色空间/线性化，使用未参与拟合的色块、位置、照明与姿态验证；报告灰阶、色差、零/255截断、红绿可分离性，而非仅纸面变白。不要用两个块+纸拟合完整色矩阵并宣称泛化。
5. 单独检查原始采集PNG与编码视频的相同帧路径、RGB/BGR及色彩元数据；本轮无法证明影响大小。预处理变化通过离线策略回放后，再决定是否需要授权的相机采样/机器人验证。

官方依据（2026-11-02访问）
Linux V4L2 User Controls：不同设备控制范围及默认可不同；AWB持续调整、WB温度单位Kelvin、gamma/饱和度等控制定义。
https://docs.kernel.org/userspace-api/media/v4l/control.html
Linux Camera Control Reference：曝光绝对值单位100µs、帧间隔限制及auto/manual定义。
https://docs.kernel.org/userspace-api/media/v4l/ext-ctrls-camera.html
OpenCV Video I/O flags：属性实际效果依赖设备硬件、驱动与API backend，不可把CAP_PROP支持视作物理效果验证。
https://docs.opencv.org/4.13.0/d4/d15/group__videoio__flags__base.html
OpenCV Color Correction Model：使用色卡检测色与参考色/颜色空间，输入RGB而非BGR；支持独立色块参考及线性化等。用于说明下一步方法，不代表本次做了CCM。
https://docs.opencv.org/4.13.0/d1/dc1/tutorial_ccm_color_correction_model.html
