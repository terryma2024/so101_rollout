# SO101 SmolVLA：训练与 Rollout 计划（2026-10-30）

**目标：** 一个 SmolVLA 根据指令选择红色或绿色方块并放入纸碗；首先验证本机环境和推理速度，再准备多任务数据与微调，最后做配对实机评测。

**实施方式：** 主 Agent 负责方案、进展沟通和验收；SubAgent 承担环境、数据、训练和 Rollout 的长程工作。用户先授权本机环境与离线测试，后进一步授权双任务数据、训练脚本、本机训练smoke、antzb独立依赖安装，以及RED ACT成功结束后自动启动首轮微调。实机运行仍为后续阶段。

**技术路线：** LeRobot 0.6.1、官方 `lerobot/smolvla_base`、本机 RTX 5060 Ti 16 GB 推理、antzb RTX 5080 16 GB 微调。SmolVLA 环境独立于现有 ACT 环境；最终版本、Hub revision、依赖和实测参数以实验清单为准。

### P2：本机离线 smoke test 与控制预算（本次执行）

使用真实录制的双相机观测和6维状态，分别输入红、绿指令，走预处理→策略推理→动作反归一化的真实链路。base 输出只用于检查形状、有限数值与耗时，不用于机械臂动作，也不据此评价抓取能力。

- [x] 保存第一次推理耗时，至少5次warmup后测至少30个完整动作块，目标50个；CUDA计时在边界显式同步。
- [x] 记录模型真实推理次数，分开测完整chunk生成、命中动作队列的 `select_action`、chunk边界tick和处理器开销。
- [x] 保存逐次原始计时，并报告 p50/p95/p99/max、50 ms超时比例、最长停顿、实际chunk长度/执行步数、dtype、推理去噪步数和显存峰值。
- [x] 如硬件支持，比较FP32与BF16；保留默认配置作为基线，不以降低模型计算量后的数字替代基线。
- [x] 以50ms预算做节拍回放，记录计算超时和动作就绪间隔，不能仅累加动作数后除以总耗时。当前采用每tick睡满剩余时间，不测试全局deadline追赶调度。录像读取缓存与是否计入计时须说明。
- [x] 输出结论区分下列三层，不用平均chunk吞吐宣称同步控制达标。

| 层次 | 判据 | 本次可证明的范围 |
|---|---|---|
| 模型/处理器可运行 | 能加载、语言进入模型、输出有限且维度正确 | 环境和离线执行链路 |
| chunk供应速度 | 生成耗时相对 `n_action_steps / 20` 的余量 | 异步执行可行性的必要条件 |
| 同步20 Hz预算 | 每次端到端tick≤50 ms，特别关注chunk边界p95及max | 已录制观测下的计算预算；不包含真实相机/串口 |

若同步边界超过50 ms，优先评估后台提前生成动作块，之后再验证队列饥饿、观测陈旧和动作衔接。异步/RTC属于另一个待验证运行模式，不把离线吞吐等同于已经实现。若计算余量仍不足，再评估降低图像/采样计算量或降低频率对性能的影响。

产物位于 `/data/work/so101-evidence/real-robot/smolvla-local-smoke-20261030/` 的独立run目录，包含环境清单、模型revision、原始样本、汇总和复现命令。可复用脚本归入 `tools/`。

### P2A：异步提前推理验证（已完成）

用户在同步smoke后授权“验证异步提前推理”。本次仍为本机录像回放，不连接硬件。

[正式结果](../experiments/smolvla-async-20261030.md)：FP32下90秒1800个有效动作、零断粮/跳步，动作间隔P99为50.038ms、max50.077ms；在途旧generation结果隔离和压力检测通过。基础动作供应计算预算通过，RTC、真实闭环与平滑性仍待验证。

- [x] 单个后台worker独占模型及处理器，在其CUDA stream完成推理、反归一化和整块动作转CPU；执行线程只处理CPU队列。
- [x] 采用有界单一在途请求，剩余10步（500ms）预取新块。动作按观测请求tick对齐，丢弃返回时已过期的前缀，再替换未来区间；禁止从过期action0继续追加。
- [x] 绝对20Hz时间表回放至少60秒，目标90秒及至少30个真实新chunk；超过5ms调度宽限时跳到未来tick并显式记skip，不突发补跑。冷启动预填充和任务切换等待单独计时，不纳入稳态结果。
- [x] 保存实际动作间隔、调度迟到、CPU消费开销、队列深度、推理延迟、观测年龄和动作块接缝差；饥饿不得用未标记的hold动作掩盖。
- [x] 用generation隔离任务/reset；真实推理链路在途切换指令，确认旧generation结果被拒绝（未按CUDA event证明切换瞬间kernel在执行）。模型reset只能由拥有模型的worker执行。
- [x] 加人工延迟压力场景及确定性回归测试，证明延迟超出缓冲预算时能被识别为失败。

初步验收针对离线计算调度：零断粮、零跳过tick、零过期/跨任务动作被消费；平均频率19.8–20.2Hz、动作间隔P99≤60ms且max≤75ms、每tick CPU工作≤50ms。保留全部原始数据，阈值并不等同于硬实时保证。冷启动、切任务等待和压力测试独立报告，不并入正常稳态指标。

使用官方SmolVLA模型执行基础的时间对齐异步队列，**不等于验证RTC的动作前缀引导、真实`lerobot-rollout`入口或实际运动平滑性**。本机0.6.1已有RTC引擎；后续实机接入应验证所选正式引擎及其reset/在途结果隔离，不将probe通过直接视为P4完成。

证据写入 `/data/work/so101-evidence/real-robot/smolvla-async-20261030/` 的独立run目录；脚本和有意义的调度/并发测试归入`tools/`与`tests/`。

### P5：配对实机评测（后续）

总计 **10种物理布局 × 2条指令 × 3次重复 = 60条**。覆盖green B2/B1和red A4/C2、D1/C1等既有困难区域，并保留常规位置。

正式60条开始前冻结检查点、推理参数和判定规则。开发阶段用于选择检查点的小批量试跑单独记录，不纳入这60条；若反复使用同一评测集挑模型，必须将其标为开发/回归评测，不能继续称作独立留出测试。

同一布局下固定红、绿方块各自的真实位置及角度、碗和相机，仅切换指令；每条结束后恢复原布局。不能沿用旧ACT评测表中随目标颜色交换方块颜色的方式。按配对布局交替或随机顺序执行，保留顺序和全部失败。

逐条独立记录：

- 指令颜色、实际首次选择颜色、是否首次抓起成功、最终目标稳定入碗。
- 干扰块触碰/误抓、重试次数、人工协助和停止原因；未知信息标unknown。
- 检查点、配置、布局/偏移/角度、光照检查、控制延迟及队列饥饿事件。

预先约定第一版候选门槛：颜色选择至少57/60、最终成功至少51/60、无人工协助；任一任务单独报告，不能由总体均值掩盖单色退化。这是项目拟定目标，非已有结果。报告样本数和不确定性，并与ACT历史基线区分协议差异；要声称优于ACT，应在相同物理布局和判定规则下重测ACT。
